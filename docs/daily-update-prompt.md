# 毎日の更新（スケジュール）に設定する指示文

全県（北信・東信・中信・南信）に広げたあとの、毎日の更新用の指示文の案です。スケジュールの設定にそのまま貼れます。
地区ごとにサブエージェントを並行して動かす形にしています。1つの流れで約100校を順に見ると長くなりすぎるためです。

---

中学校教員の瀧川翔太さんが中学3年生に配るWebサイト「長野県高校進学ナビ」（入試ナビ・イベントナビ）の毎日の更新作業です。返答はすべて日本語。

サイトは GitHub リポジトリ hs-navi/chushin-navi の main ブランチで、GitHub Pages（https://hs-navi.github.io/chushin-navi/）として公開されています。このリポジトリは実行開始時にクローン済みです。

【手順】
1. git checkout main と git pull origin main で最新の main にする。リポジトリの CLAUDE.md を読み、そこに書かれたルール（情報源・表記・データ形式・地区とデータの分割・更新手順）に必ず従う。
2. data/regions.json の status が active または partial の地区（北信・東信・中信・南信）ごとに、サブエージェントを1つずつ、並行して起動する。各サブエージェントには次を伝える。
   - 担当する地区の id（hokushin / toshin / chushin / nanshin）。
   - 書き換えてよいのは、その地区のファイル（data/events-<地区id>.json と data/nyushi-<地区id>.json）だけ。共通のファイル（data/events.json、data/nyushi.json、data/regions.json）と、ほかの地区のファイルは書き換えない。
   - その地区の events-<地区id>.json の schools[] の全校の url と、全イベントの src を一つずつ必ず開いて確認し、各校の「中学生の皆さんへ」「入試情報」「お知らせ」ページも見る。一部の学校だけで終わらせない。PDF の中身が文字として読めない場合は、curl で作業フォルダに保存し、Read ツールでページを画像として見て読み取る。robots や 403 などで取得できないページを別の方法で取りに行かない（その場合は県教委の一覧にある日付だけを残し、「要確認」にする）。
   - events-<地区id>.json：新しく公表された行事の追加、日程・時間・締切・申込方法の変更や中止の反映、二次情報の行事が公式で確認できたら secondary を外して src を公式に差し替え。終わった行事は消さない。
   - nyushi-<地区id>.json：私立・通信制の令和9年度入試日程・内容が公式に出ていれば反映し、status を "ok" にする（未公表なら warn のまま）。公立の日程・学校別実施内容に変更があれば反映する。「要確認」の項目が公式資料ではっきり確認できたら直す。
   - 公式に書いてあることだけを書く。推測や昨年度の日付を今年度として載せない。
   - 最後に、変更した内容を学校名つき・出典リンクつきで短く報告する（変更がなければ「変更なし」）。
3. サブエージェントを待つ間に、全県共通の情報を自分で確認する。
   - 県教委の令和9年度入学者選抜の関係日程（r9_nittei.pdf）と、学校別実施内容一覧（r9-1-01〜06.pdf）。変更があれば data/nyushi.json の publicSchedule と、各地区の publicSchools に反映する。令和9年度の募集学級数は11月に発表される予定なので、発表されたら反映する。
   - 県の私立高等学校名簿（休校・閉校・新設の変更）。
4. すべてのサブエージェントが終わったら、報告をまとめる。サブエージェントが失敗した地区があれば、その地区は変更しないまま、報告に書く。
5. 内容を変えた日は data/nyushi.json の updatedAt を今日（日本時間）にする。data/events.json と data/nyushi.json の checkedAt は、変更がなくても必ず今日の日付（日本時間）に書き換える。
6. node scripts/check.mjs が OK になることを確認する。エラーが出たら直してから進む。直せない場合はコミットせずに報告する。
7. checkedAt を更新しているので、毎日必ずコミットする。変更点が分かる日本語のメッセージでコミットし（変更が checkedAt だけなら「確認日を更新（新しい情報なし）」）、claude/ のブランチではなく main ブランチに直接 push する。push 前に git fetch origin main をして、必要なら rebase する。push が権限エラーになった場合はその内容を報告する。
8. 最後に、追加・変更した行事や入試情報を、地区・学校名つきで短く報告する（出典リンク付き）。変更がなければ「今日は新しい情報なし」と一行で報告する。

---

## 補足

- 1回の実行は長くなります（4地区を並行して確認し、約100校のページを開きます）。途中で止まった地区があっても、他の地区の結果は使えるようにしています。
- 負担を減らしたいときは、2・3日で1回転する形（地区ごとに曜日を分ける）にもできます。その場合は、地区ごとの確認日（`checkedAt`）を `data/regions.json` に持たせて、画面に地区ごとの確認日を出す変更が必要です。
